# Input Parameters

The concentrated leak erosion (CLE) core compaction model takes two kinds of input. Most are the inputs shared by the CLE family, documented in
full in the
[Input Parameters](https://usace-rmc.github.io/RMC-Software-Documentation/docs/web-applications/system-response/cle-common-methods-screening/v1.0/input-parameters)
chapter of the CLE Common Methods manual: the hydraulic loading, the unit system and datum convention, the embankment description, the
failure-pathway inputs, the upstream seepage-limiting elements, the initiation material inputs of the compaction models, and the intervention and
breach probabilities. The rest are specific to this mechanism: the normal pool elevation, the flaw-factor selections, and the leakage observation.
This chapter states the unit system, documents the mechanism-specific inputs in full, and then states how the model takes each shared input where
the family allows more than one form.

## Unit System

The model takes a unit system input, US customary (the default) or SI. All elevations and lengths are entered in the length unit of that system
(feet or meters) and share one vertical datum. The input changes no formula in this model, and quantities with fixed units (critical shear stress
in lb/ft², initial pipe diameter in millimeters) are stated in those units regardless of the unit system. The base-width bands of the section
geometry factor are applied to the base width as entered, with no unit conversion (see
[Flaw Assessment](./04-flaw-assessment.mdx#section-geometry-factor)). The datum convention shared by the CLE family is documented in
[Unit System](https://usace-rmc.github.io/RMC-Software-Documentation/docs/web-applications/system-response/cle-common-methods-screening/v1.0/input-parameters#unit-system)
in the CLE Common Methods manual.

The normal pool elevation $z_{np}$ is the lower reference of the heuristic that places the base of the flaw one third of the way from the normal
pool to the crest (see [Flaw Assessment](./04-flaw-assessment.mdx#base-of-flaw-elevation)). It is supplied directly and is not taken from the
headwater series. The crest elevation $z_c$ must be above it. The normal pool is required even when an observation of leakage sets the base of the
flaw, although it then has no effect on the result.

### Core Compaction Category

The core compaction category describes the compaction equipment and effort used to place the core material, which govern the layer thickness and
the degree of compaction achieved. It is the most heavily weighted factor of the flaw assessment (see
[Flaw Assessment](./04-flaw-assessment.mdx#compaction-factor)). The categories are:

- **Well compacted** — soil compacted by suitable rollers, with discing and a layer thickness appropriate to the equipment. This is the least
  likely condition for a continuous poorly compacted zone.
- **Poorly compacted** — soil placed and compacted by bulldozer without compaction by rollers, or rolled in thick layers.
- **Very poorly compacted** — no formal compaction; for example, material pushed into place by excavator or bulldozer in very thick layers. This
  is the most likely condition for a continuous poorly compacted zone.
- **Unknown** — the compaction equipment and effort cannot be determined from the construction records or other available information.

Unknown is entered whenever the available records do not support one of the three judged categories. It is scored conservatively, between Poorly
compacted and Very poorly compacted, so that missing documentation does not lower the screening result (see
[Flaw Assessment](./04-flaw-assessment.mdx#compaction-factor)).

The category is required unless an observation of leakage or wet spots is reported. When the observation is reported, the category is optional; if
it is supplied, the model still scores it and reports the scores, but the scores do not affect the result.

### Flaw Base Width and Flaw Height

The section geometry factor of the flaw assessment bands the base width $W$ of the embankment section and its width-to-height ratio $W/H_s$, where
$H_s$ is the section height (see [Flaw Assessment](./04-flaw-assessment.mdx#section-geometry-factor)). By default both are derived from the
embankment section the model uses — the core section when one is supplied, the shell section otherwise — as described in
[Section Geometry Used in Scoring](https://usace-rmc.github.io/RMC-Software-Documentation/docs/web-applications/system-response/cle-common-methods-screening/v1.0/flaw-conventions#section-geometry-used-in-scoring)
in the CLE Common Methods manual.

Either dimension may be supplied instead, and each must then be positive. A supplied value replaces the derived value in the flaw scoring only; the
initiation analysis always uses the embankment section itself. The section must still resolve to a positive height and base width.

Reporting that leakage through the embankment, or wet spots, have been observed exiting the downstream face states that the flaw is demonstrated.
The flaw probability is then 1.0, whatever the compaction category and the section geometry would score, and the base of the flaw is set to the
observed elevation (see [Flaw Assessment](./04-flaw-assessment.mdx#observation-override)). When no observation is reported, the flaw probability is
scored.

The leakage or wet-spot elevation $z_{lk}$ is the elevation at which the observed leakage or wet spots exit the downstream face of the embankment.
It is required when an observation is reported and becomes the base of the flaw, replacing the normal-pool heuristic. Like any base of the flaw, it
must lie within the embankment section used for initiation: at or below the top of that section, at or above the lowest segment bottom of each
face, and at a positive elevation (see [Flaw Assessment](./04-flaw-assessment.mdx#base-of-flaw-elevation)).

## Shared Inputs

The shared inputs are documented in the CLE Common Methods manual. Where the family allows a choice, the core compaction model takes them as
follows.

- **Hydraulic loading** — a headwater series and an optional tailwater series, as described in
  [Hydraulic Loading](https://usace-rmc.github.io/RMC-Software-Documentation/docs/web-applications/system-response/cle-common-methods-screening/v1.0/input-parameters#hydraulic-loading).
  Tailwater reduces the net head across the flaw in the initiation analysis.
- **Embankment description** — the crest elevation $z_c$, the embankment type, the shell section, and the optional core section, as described in
  [Embankment Description](https://usace-rmc.github.io/RMC-Software-Documentation/docs/web-applications/system-response/cle-common-methods-screening/v1.0/input-parameters#embankment-description).
  When a core section is supplied, it is used for both the flaw scoring and the initiation analysis, whatever the embankment type; otherwise the
  shell section is used. A partially described core section leaves the inputs inconsistent, and the analysis is not evaluated; the shell is not
  substituted for it. The embankment type sets only the crack-filling probability. The crest elevation, not the top of the core, is the upper
  reference of the base-of-flaw heuristic.
- **Filter presence and continuation inputs** — this model has no separate filter-presence selection. Supplying the filter and base-soil
  description of the shared continuation method states that a filter intercepts the failure pathway at the base of the flaw; omitting it states
  that none does (see
  [Failure-Pathway Inputs](https://usace-rmc.github.io/RMC-Software-Documentation/docs/web-applications/system-response/cle-common-methods-screening/v1.0/input-parameters#failure-pathway-inputs)
  and the
  [Input Parameters](https://usace-rmc.github.io/RMC-Software-Documentation/docs/web-applications/system-response/continuation-screening/v1.0/input-parameters)
  chapter of the Continuation (Filter Evaluation) Screening manual). The model does not compare the filter with any elevation, so whether the
  filter reaches the base of the flaw is resolved before the description is supplied.
- **Embankment materials** — the USCS classes of the materials the pipe passes through, at least one, which set the roof-support probability. The
  core soil classification is not added to this list automatically; the core material is listed here if the pipe passes through it.
- **Upstream seepage-limiting elements and top-of-wall elevation** — as described in
  [Upstream Seepage-Limiting Elements](https://usace-rmc.github.io/RMC-Software-Documentation/docs/web-applications/system-response/cle-common-methods-screening/v1.0/input-parameters#upstream-seepage-limiting-elements).
  A top-of-wall elevation may be given only when a wall is among the elements, and is compared once with the base of the flaw.
- **Initiation material inputs** — the core soil classification and the optional critical shear stress, initial pipe diameter, and seepage path
  length, as described in
  [Initiation Material Inputs](https://usace-rmc.github.io/RMC-Software-Documentation/docs/web-applications/system-response/cle-common-methods-screening/v1.0/input-parameters#initiation-material-inputs).
  Left blank, the initial pipe diameter takes this model's default distribution, listed in
  [Initial Pipe Diameter](https://usace-rmc.github.io/RMC-Software-Documentation/docs/web-applications/system-response/cle-common-methods-screening/v1.0/initiation#initial-pipe-diameter)
  in the CLE Common Methods manual (see [Event Tree](./05-event-tree.mdx#node-2-initiation)).
- **Intervention and breach** — the probabilities of unsuccessful intervention and of breach, as described in
  [Intervention and Breach](https://usace-rmc.github.io/RMC-Software-Documentation/docs/web-applications/system-response/cle-common-methods-screening/v1.0/input-parameters#intervention-and-breach).
