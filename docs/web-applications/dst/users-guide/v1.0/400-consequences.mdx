# Consequences

The Consequences module estimates the life loss and economic damages downstream of the dam, with and without a dam failure. The screening
team builds a two-dimensional hydraulic model below the dam, simulates the flood at each loading level with HEC-RAS, and then simulates life loss
and damages in each flood with LifeSim. The results become the consequence functions that the Risk Analysis module uses (see
[Risk Analysis](./500-risk-analysis.mdx)).

The module has six pages, reached from **Consequences** in the module navigation. The work follows their order:

- [Inundation Geometry](./401-inundation-geometry.mdx): build the hydraulic model (model area, dam, rivers, terrain, land cover and mesh).
- [Inundation Analysis](./402-inundation-analysis.mdx): set the loading levels, boundary conditions and breach of each analysis, and run the flood
  simulations.
- [Consequence Data](./403-consequence-data.mdx): add the structure inventory, rate the Emergency Response and add an optional non-failure hazard
  zone.
- [Consequence Analysis](./404-consequence-analysis.mdx): set when each hazard occurs and how much notice people have, and run the consequence
  simulations.
- [Results Map](./405-results-map.mdx): review the consequences of one loading level, structure by structure.
- [Results Data](./406-results-data.mdx): review each consequence function as graphs and tables, and enter functions by hand.

None of these pages is verified. Their inputs are read-only to users who are not on the screening team and while the screening's inputs are locked
(see [Input Lock](./040-working-in-dst.mdx#input-lock)). The flood and consequence simulations run only when the user starts them. Changing an
input does not clear their results; DST marks the results out of date until the simulation runs again. The methods behind the simulations are
described in the HEC-RAS and LifeSim documentation and in the DST Technical Reference Manual.
