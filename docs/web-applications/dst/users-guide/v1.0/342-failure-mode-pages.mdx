# Failure Mode Pages

Every failure mode page shares a common set of parts: the choice of the location's cross section and SRP mode, entered and overridden inputs,
justifications for departures from DST defaults, verification of the location and readiness for submission. [Common Problems](#common-problems) at
the end of this page explains why a system response does not calculate, why verification is refused or cleared, and why a location stays
Incomplete.

Each failure mode page opens with a heading that gives the failure mode's full name and a toolbar, and ends with the **Failure mode summary** tray.
The sections between them belong to each failure mode, and its own page in this guide describes them. Most failure mode pages have one or more
characterization sections followed by a **System Response** section; the event-tree pages instead have **Stages to evaluate**, **Event tree
evaluation** and **System Response** (see [Event Trees](./344-event-trees.mdx)).

Inputs on a failure mode page save automatically (see [Saving](./040-working-in-dst.mdx#saving)), and the system response recalculates
automatically when an input changes (see [Automatic Calculation](./040-working-in-dst.mdx#automatic-calculation)). The page messages button lists
the page's errors, warnings and required inputs (see [Page Messages](./040-working-in-dst.mdx#page-messages)).

## Characterization

The characterization sections describe the location in the terms the failure mode's model uses. Every failure mode page uses the same kinds of
input:

- **Read-only facts.** Values DST takes from other pages, such as the embankment height from the selected cross section or elevations from the Dam
  Data page. They show a dash until the source page provides them. To change one, the user edits it on its source page.
- **Screening facts.** Answers from the Failure Mode Screening questionnaire that the model reads. The information icon beside each names its
  source, for example **From Failure Mode Screening, step 4**, with a link to that step. An unanswered question reads **Not answered**.
- **Entered inputs.** Values the user enters or chooses on the page. Each failure mode's page in this guide lists their ranges and defaults.
- **Inputs with a DST default.** Inputs that DST fills in, such as a material taken from the cross section drawing, carry an **Auto** badge.
  Resting the pointer on the badge explains where the value comes from. When the user changes the value, the badge reads **Manual**, and the revert
  button (circular arrow) beside it restores the DST value.
- **Figures.** Many pages draw the selected cross section or a profile of the location, with the zones and dimensions the model uses highlighted.
- **Information icons.** Selecting the icon beside a label opens a short explanation of what the input represents to the model.

Changing a characterization input recalculates the system response, which clears any nodal revisions of the location (see
[Nodal Revisions](./343-system-response.mdx#nodal-revisions)).

recalculates the system response.

## Justifications

Each value that departs from the DST default needs a written justification: a parameter override, an input with a **Manual** badge that carries a
justification chip, and every node with a nodal revision. The chip beside the value reads **Add justification** until a justification is entered and
**Justification** afterward. Selecting it opens a box for the text, which saves when the user leaves it.

The **Failure mode summary** tray collects all justifications of the location, where they can also be entered (see
[Failure Mode Summary](#failure-mode-summary)). A missing justification leaves the location Incomplete on the Submission Readiness page.

## Failure Mode Summary

The **Failure mode summary** tray gathers everything about the location that departs from DST defaults, so that the departures can be reviewed and the
justifications and the system response rationale entered in one place. The tray runs along the bottom of every failure mode page. Collapsed, it shows
a status such as "1 Unknown · 2 overrides · 1 needs justification · No rationale yet". Selecting it opens the tray, which works like the other summary
trays (see [Summary Tray](./040-working-in-dst.mdx#summary-tray)). <FigReference figKey="dst-users-guide-fig-failure-mode-evaluation-summary-tray" />

## Calculation

DST calculates a location's system response whenever the page opens or an input changes and the inputs are complete. While it runs, the System
Response chart shows a placeholder curve, and the results fill the table and chart when it finishes. An edit made during a run replaces it: DST
calculates again with the new inputs. Each user runs one calculation at a time, so with two failure mode pages open, the second waits for the first.

A calculation that cannot run, or runs into trouble, reports it in the page messages (see
[A calculation fails or waits](#common-problems)).

## Verifying a Location

A member of the screening team verifies each location on its own failure mode page with the verification badge in the sub-navigation bar (see
[Human Verification](./040-working-in-dst.mdx#human-verification)). Resting the pointer on the badge names what is being verified, for example
**PFM-01 SRP — Left Abutment**. In DST Based SRP or Event tree mode, verification needs a current calculated system response; a user-defined SRP
needs no calculation to be verified.

Any saved change on the page clears the location's verification: its name, cross section, SRP mode, characterization inputs, overrides, nodal
revisions, user-defined SRP, justifications or system response rationale. A change on another page that clears the location's results also clears
its verification.

:::tip

The team verifies a location last, after the justifications and the system response rationale are complete, since editing either one clears the
verification.

:::

## Submission Readiness

Each location has its own tile on the Submission Readiness page, such as **PFM-01 · Left Abutment** (see
[Submission Readiness](./040-working-in-dst.mdx#submission-readiness)). The tile lists what keeps the location from being ready, with the failure
mode and location first: each error and required input of the page, for example "PFM-01 — Left Abutment: Select a cross section for this
location.", and a system response that has not been calculated or is out of date. For an event-tree location in **Event tree** mode it also counts
the incomplete nodes, for example "PFM-11 — Location 1: 2 nodes missing probabilities, 3 missing rationales." A missing justification or system
response rationale leaves the location Incomplete.
