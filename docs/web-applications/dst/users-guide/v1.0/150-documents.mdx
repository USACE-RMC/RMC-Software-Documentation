# Documents

The Documents module is the screening's library of reference files: reports, drawings, photographs, spreadsheets and any other file the screening
team relies on. Each document can be linked to the pages it supports, such as Dam Data or a failure mode location. A linked document then appears in
the Supporting documents section of that page's summary tray. When a screening is copied, its documents and their page links go with it, except links
to failure mode locations.

## The Documents Page

The module has a single page, **Documents**, reached by selecting **Documents** in the module navigation.

Everyone on the screening can open and download its documents. The Facilitator, Team Members and administrators can also add, edit, link and delete
documents; for them the page shows **Add Document**, the selection check boxes and the Edit and Delete buttons. Documents stay open to these changes
while the screening is under review, and become read-only once the screening is complete. The page has nothing to verify and does not count toward
Submission Readiness.

Before any document is added, the page shows "No documents uploaded yet". For the screening team, the text beneath it reads "Upload reports, drawings,
photos, and other reference files so the whole team can find them in one place.", followed by "Drag files onto this page, or" above the **Add
Document** button; for everyone else it reads "Documents uploaded by the screening team will appear here."

Once the library holds documents, the screening team also sees "Drag files onto this page to add them to Documents." below the list, beside the page
controls, as a reminder that files can be dropped anywhere on the page (see [Adding Documents](#adding-documents)). The drag prompts appear only on
computers with a mouse or similar pointer; on touch screens, files are added with **Add Document**.

## Adding Documents

**Add Document** opens the **Add Documents** dialog (<FigReference figKey="dst-users-guide-fig-documents-add" />). Files dragged from the computer onto
the Documents page open the same dialog with those files already listed; while files are dragged over the page, it reads "Drop files to add them to
Documents".

DST checks each file as it is added. A file it cannot accept is struck through, with the reason, and is left out of the upload:

- "Not a supported file type"
- "The file is empty"
- "Larger than the 5 GB limit"

Adding more than 100 files at once leaves the extras out, with a notice such as "Only 100 files can be added at a time, so 3 left out."

DST also warns, without refusing the file, when "A document with this name already exists" or "This file name is listed more than once". Folders cannot
be uploaded; DST reports that the files inside them must be dropped instead. Closing the dialog with files listed asks "Discard these files?";
**Discard** closes it and drops the files with their descriptions and links, and **Keep editing** returns to the dialog.

Each file row ends with an × button, "Remove from this upload", which takes that file out of the list before the upload, with its description and
links. The other files stay as they are.

Files can be dropped only on the Documents page or on the drop zone of an Add Documents dialog. A file dragged anywhere else in DST is refused: the
pointer shows that it cannot be dropped, and releasing it does nothing, so the browser does not open the file in place of DST.

While files upload, a panel in the corner of the screen reads, for example, "Uploaded 1 of 3 files" with a progress bar and the note "Keep this tab open
until uploads finish." beside a **Cancel all** button. Its details list each file, marked **Waiting** until its turn, with a button to cancel it; a file that fails offers **Try
again**. When the uploads finish, the panel reports the result, for example "3 files uploaded", or "2 uploaded, 1 failed" when a file fails, and each new
document appears on the page. Logging out while files are
still uploading asks "Stop uploading?"; **Keep uploading** returns to DST, and **Stop and log out** ends the uploads and the session.

The panel's header holds two buttons. **Show details** and **Hide details** open and close the list of files, and **Close**, shown once every
upload has finished, removes the panel. When every file uploads successfully, the panel also closes on its own a few seconds later; when a file
fails, it stays until the user closes it, so the failure is not missed.

Uploads belong to the browser tab, not to the Documents page. Once **Upload** is selected, the files keep uploading while the user moves to other
DST pages, or to another screening, and the panel stays in the corner of the screen. Closing the tab, reloading it or leaving DST for another site
while files are still uploading makes the browser ask whether to leave the page, in the browser's own words; leaving stops the uploads that have not
finished.

## Finding Documents

The toolbar above the documents narrows and arranges the list. It appears once the screening has at least one document.

- **Search documents** matches any part of a file name, description, the name of the user who uploaded it or the name of a linked page.
- **File type** shows one kind of file, from the groups in <TableReference tableKey="dst-users-guide-table-documents-file-types" />, or **All types**.
- **Linked to** shows the documents linked to one page, those linked to no page (**Unlinked**), or **All pages**. It lists only the pages that have
  linked documents.
- **List view** and **Grid view** switch the layout. DST remembers the choice in that browser, for every screening, and the **Link existing**
  picker in a summary tray shares it (see [Supporting Documents](#supporting-documents)).
- **Rows per page** (list view) or **Files per page** (grid view) shows 15, 25 or 50 documents, and the page controls below the list move between pages.

When the filters hide every document, the page reads "No documents match your filters." The search, the filters and the number per page are not
remembered: each time the Documents page opens, it shows all documents, 15 per page.

In list view, each document is a row with the columns in <TableReference tableKey="dst-users-guide-table-documents-columns" />. On narrower screens the
table drops the Uploaded By, Size, Uploaded and Linked To columns, in that order, as space runs out.

## Opening and Downloading

PNG and JPG images open in an image viewer over the page. The viewer shows the file name, the image and its description, or "No description".
**Previous** and **Next**, or the Left and Right arrow keys, move among the images in the current list, and the viewer's buttons open the image in a
new browser tab or download it. Every other kind of file downloads when the user selects its name. **Open in new tab** appears only for PNG and JPG
images, and **Download** for every file; other images, such as TIFF or GIF files, download.

## Editing and Linking Documents

**Edit** opens the **Edit Document** dialog, which shows the file name and holds the document's **Description** (up to 2,000 characters) and its page
links. The file itself cannot be replaced; a new version is added as a new document. **Save** applies the changes.

The links list, headed **Linked to**, reads "Not linked to any page" until a link is added. Each link names its page and has a locator box and a
**Remove link** button:

- **Add link to a page…** chooses a page to link. The pages are Dam Data, Operational Data, Flood Hazard, Stage Duration, Seismic Hazard, Dam
  Information, Failure Mode Screening, Failure Mode Selection, each failure mode location, Inundation Geometry, Inundation Analysis, Consequence Data,
  Consequence Analysis, Results Map, Results Data, Risk Analysis Setup, Risk Analysis Results, Risk Characterization, Major Uncertainties, Summary of
  Findings and Recommendations.
- **Locator** (optional, up to 200 characters) says where to look in the file for that page, for example "p. 47, Table 6".

To link several documents to one page at once, the user selects their check boxes in the list or the grid and chooses the page in
**Link selected to a page…** in the selection bar, which replaces the toolbar while documents are selected and counts them, for example "3 selected".
In grid view, **Select all** selects every document that matches the filters.

## Deleting Documents

**Delete** on a document opens the **Delete Document** dialog: "Delete" followed by the file name and "This can't be undone." When the document is linked
to pages, the dialog names them and notes that deleting removes the document from every linked page. **Delete** confirms.

:::caution

Deleting a document removes the file from the screening permanently, along with its links to every page. It cannot be restored.

:::

To delete several documents, the user selects them and selects **Delete** in the selection bar. The **Delete Documents** dialog lists the files and
notes when they are linked to pages; its button names the count, for example **Delete 3 documents**.

## Supporting Documents

Every summary tray ends with a **Supporting documents** section, described as "Files from the screening's Documents that support this page." It shows
the documents linked to that page as tiles, with their locators
(<FigReference figKey="dst-users-guide-fig-documents-supporting" />). [Summary Tray](./040-working-in-dst.mdx#summary-tray) describes how the
summary tray itself works.

For the Facilitator, Team Members and administrators, the section offers:

- **Link existing** — opens **Link documents to** followed by the page name, a picker of the screening's documents with the same search and filters as
  the Documents page. Documents already linked are marked **Linked**. The user selects documents and selects the button that names the count, for
  example **Link 2 documents**. When the screening has no documents yet, the picker reads "No documents have been uploaded to this screening yet."
- **Upload** — opens **Add Documents to** followed by the page name. It works like the Add Documents dialog, except that every file is linked to this
  page: each file row has a **Locator** box ("Locator, e.g. p. 47", up to 200 characters) in place of the links button, and the dialog has no file
  check boxes and no **Link selected to a page…** bar.
- **Page or section** — the locator box under each tile, which saves when the user leaves it.
- **Unlink** — in each tile's menu, removes the document from this page only; the document stays in Documents and on its other pages.
- **Delete** — in each tile's menu, deletes the document from the screening. Its dialog also offers **Unlink instead**, which removes the document
  from this page only.

Other users see the tiles and their locators, and can open and download the files. With nothing linked, the section reads "No documents linked to
this page yet.", followed for the screening team by "Link a file from Documents or upload a new one."
