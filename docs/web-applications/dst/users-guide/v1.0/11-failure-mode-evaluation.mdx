# Failure Mode Evaluation

The Failure Mode Evaluation page, under the Response module, lists every potential failure mode (PFM) the screening team selected for evaluation on
the Failure Mode Selection page (see [Chapter 10, Failure Mode Screening and Selection](./10-failure-mode-screening-and-selection.mdx)). From it, the
user adds the locations at which each PFM is evaluated and opens each location's failure mode page. On that page the user characterizes the
location and defines its system response probability (SRP), the curve that the Risk Analysis module uses for that location.

This chapter describes the Failure Mode Evaluation page and the parts that every failure mode page shares: locations, the page toolbar, the
characterization pattern, parameter overrides and justifications, the Failure mode summary, the system response with its nodal tables and nodal
revisions, and the event tree used by PFM-11, PFM-12, PFM-13, PFM-17, PFM-18, PFM-20, PFM-22 and PFM-23, and by PFM-21 for a concrete dam with no
Gravity or Roller-Compacted Concrete type. Chapters 12 through 30 describe each failure mode page's own inputs and refer back here for the shared
parts. The DST Technical Reference Manual and the System Response Library manuals document the methods behind each SRP.

### The system response preview

The **System Response Preview** card plots the active SRP of every Defined location on one chart, so the team can compare them. The chart is
read-only; the team defines each curve on its own failure mode page. The subtitle counts the curves, for example "Showing 3 of 3 curves · read-only". The
horizontal axis is **Headwater Elevation (ft)**; DST places curves defined against overtopping depth on it using the location's crest elevation.

<FigReference figKey="dst-users-guide-fig-failure-mode-evaluation-curves-menu" /> shows the **Curves** list, which opens from the button in the
chart's upper right corner.

- **Showing and hiding curves.** A check box beside each curve shows or hides it; a failure mode's group check box shows or hides all of its
  locations. **Show all** and **Hide all** act on every curve. When every curve is hidden, the chart reads "All curves are hidden. Use Curves to show
  them." The choice is not saved and resets when the page reloads.
- **Curves not yet drawn.** The list shows a location that is Incomplete or Not started with its status and an **Open** link to its failure mode page. A
  location whose cross section has no crest elevation shows a **No crest** tag: DST cannot place its overtopping curve on the elevation axis.
- **Highlighting.** Resting the pointer on a curve in the list or in the key below the chart highlights that curve.
- **Empty chart.** Before any location is Defined the chart reads "No system response defined yet". When no failure mode is selected for evaluation it
  reads "Complete Failure Mode Screening and Failure Mode Selection to choose failure modes for evaluation."

The chart zooms and resets in the same way as the SRP charts on each failure mode page (see [SRP charts](#srp-charts)).

## Locations

its own failure mode page, inputs, system response and verification. A failure mode starts with one location when it is selected for evaluation.

Some failure modes allow only one location. For these, the table offers neither **Add location** nor **Copy location**, and the failure mode's

table. The menu shows no location actions to users who cannot edit the screening's inputs, and while inputs are locked (see
[Chapter 4, Working in DST](./04-working-in-dst.mdx#input-lock)).

### Adding a location

For a failure mode with one location, the user chooses **Add location** from its row menu. For a failure mode with several locations, the user
selects **Add location** (+) on its parent row. DST adds a location with no inputs, named **Location N**, where N is the new number of locations,
and the table shows the failure mode's locations as indented rows. DST creates the location at once, and its status reads Incomplete until its system response is defined.

### Copying a location

**Copy location** adds a location that starts with the same inputs, overrides, justifications and results as the row it was copied from. DST names it
after the source with **(copy)** added, for example **Left Abutment (copy)**. The copy is not verified. For a failure mode with one location, the
copy is made from that location.

### Renaming a location

Each location's name appears in the table, in the breadcrumb and on its Submission Readiness tile. The user renames a location in the **Location**
box of its failure mode page (see [The page toolbar](#the-page-toolbar)). DST does not save a blank name: system-response pages show "Name cannot be empty.", and event-tree pages keep the last saved name. **Location N** is only the label DST shows for a location stored without a name.

**Rename location** in a location's row menu opens the **Rename location** dialog with a **Location name** box. **SAVE** shows the new name in the
table, and **CANCEL** closes the dialog without a change. A blank name leaves the name unchanged.

:::note

A name entered in the **Rename location** dialog shows in the table only until the page reloads. To keep a new name, the user enters it in the
**Location** box of the failure mode page.

:::

### Deleting a location

**Delete location** in a location's row menu removes that location with its inputs, results, justifications and verification. A failure mode always
keeps at least one location, so the item appears only on failure modes with two or more locations. Links from the location to files on the
Documents page are removed; the files themselves remain (see [Chapter 6, Documents](./06-documents.mdx)).

:::caution

**Delete location** acts at once, with no confirmation, and cannot be undone.

:::

### Opening a location

Selecting a failure mode or location name, or **Open failure mode** in its row menu, opens the location's failure mode page. The sub-navigation then
shows a breadcrumb such as **Failure Mode Evaluation › PFM-01 · Left Abutment**; selecting **Failure Mode Evaluation** returns to the table (see
[Chapter 4, Working in DST](./04-working-in-dst.mdx#modules-and-pages)). Before leaving a failure mode page, DST saves any entry still in progress.

A failure mode page opens only while its failure mode is selected for evaluation. Otherwise the page shows the notice "PFM-01 isn't being evaluated"
(with the failure mode's number), reading "This failure mode isn't selected for evaluation on Failure Mode Selection. Select it for evaluation there
to open its locations." When the DST recommendation for the failure mode has changed and is not yet confirmed, opening the page returns the user to
the Failure Mode Selection page with a notice such as "The DST recommendation for PFM-01 changed. Confirm your decision on the Failure Mode Selection
page before evaluating it."

## The Failure Mode Page

Every failure mode page has the same frame: a heading with the failure mode's full name, a toolbar, the page's sections in order, and the
**Failure mode summary** tray along the bottom of the screen. The sections between the toolbar and the tray belong to each failure mode, and its own
chapter describes them. Most failure mode pages have one or more characterization sections followed by a **System Response** section; the
event-tree pages instead have **Stages to evaluate**, **Event tree evaluation** and **System Response** (see [Event Trees](#event-trees)).

Inputs on a failure mode page save automatically (see [Chapter 4, Working in DST](./04-working-in-dst.mdx#saving)), and the system response
recalculates automatically when an input changes (see [Chapter 4, Working in DST](./04-working-in-dst.mdx#automatic-calculation)). The page messages
button lists the page's errors, warnings and required inputs (see [Chapter 4, Working in DST](./04-working-in-dst.mdx#page-messages)).

### Characterization

The characterization sections describe the location in the terms the failure mode's model uses. Every failure mode page builds these sections from
the same kinds of element:

- **Read-only facts.** Values DST takes from other pages, such as the embankment height and slopes from the selected cross section or elevations from
  the Dam Data page. They show a dash until the source page provides them. To change one, the user edits it on its source page.
- **Screening facts.** Answers from the Failure Mode Screening questionnaire that the model reads. The information icon beside each names its
  source, for example **From Failure Mode Screening, step 4**, with a link to that step. An unanswered question reads **Not answered**.
- **Entered inputs.** Values the user enters or chooses on the page. Each failure mode's chapter lists their ranges and defaults.
- **Inputs with a DST default.** Inputs that DST fills in, such as a material taken from the cross section drawing, carry an **Auto** badge.
  Resting the pointer on the badge explains where the value comes from. When the user changes the value, the badge reads **Manual** and a revert
  button (circular arrow) beside it restores the DST value.
- **Figures.** Many pages draw the selected cross section or a profile of the location, with the zones and dimensions the model uses highlighted.
  They update as the inputs change.
- **Information icons.** Selecting the icon beside a label opens a short explanation of what the input represents to the model.

Changing a characterization input recalculates the system response, which clears any nodal revisions of the location (see
[Nodal revisions](#nodal-revisions)).

### Justifications

Each value that departs from the DST default needs a written justification: a parameter override, an input with a **Manual** badge that carries a
justification chip, and every node with a nodal revision. The chip beside the value reads **Add justification** (amber) until a justification is
entered and **Justification** afterward. Selecting it opens a box for the text, which saves when the user leaves it.

The **Failure mode summary** tray collects all justifications of the location (see [Failure mode summary](#failure-mode-summary)), where they can
also be entered. A missing justification leaves the location Incomplete on the Submission Readiness page (see
[Chapter 4, Working in DST](./04-working-in-dst.mdx#submission-readiness)).

### Verifying a location

A member of the screening team verifies each location on its own failure mode page with the verification badge at the right of the sub-navigation bar (see
[Chapter 4, Working in DST](./04-working-in-dst.mdx#human-verification)). Resting the pointer on the badge names the unit being verified, for
example **PFM-01 SRP — Left Abutment**. In DST Based SRP or Event tree mode, verification needs a current calculated system response. When there is none, DST refuses with
"There are no calculated results to verify yet." (on event-tree pages, "The event tree has no system response yet. Complete every node's
probabilities and resolve the errors on this page, then verify."). For results from an older model version it refuses with "The SRP cannot be
verified because the stored results were produced by an older System-Response model version. Recalculate the results before verifying them." A
user-defined SRP needs no calculation to be verified.

Any saved change on the page clears the location's verification: its name, cross section, SRP mode, characterization inputs, overrides, nodal
revisions, user-defined SRP, justifications or system response rationale. A change on another page that clears the location's results also clears its verification.

### Submission readiness

Each location has its own tile on the Submission Readiness page, such as **PFM-01 · Left Abutment** (see
[Chapter 4, Working in DST](./04-working-in-dst.mdx#submission-readiness)). The page lists what keeps a location from being ready, with the failure
mode and location first: each error and required input of the page, for example "PFM-01 — Left Abutment: Select a cross section for this
location.", and a system response that has not been calculated or is out of date. For an event-tree location in **Event tree** mode it also counts
the incomplete nodes, for example "PFM-11 — Location 1: 2 nodes missing probabilities, 3 missing rationales." A missing justification or system
response rationale leaves the location Incomplete.

## System Response

The **System Response** section shows the location's SRP: the probability of the failure mode's system response at each headwater elevation (or at

### Active SRP

The SRP mode in the toolbar chooses the location's active SRP: the curve DST passes to the Risk Analysis module and shows in the System Response
Preview.

- **DST Based SRP** (**Event tree** on the event-tree pages): the curve DST calculates from the page's inputs, including any nodal revisions.
- **User Defined SRP** (**User defined**): a curve the user enters in a table (see [User-defined SRP](#user-defined-srp)). The page
  replaces its characterization and system response sections with the table and its chart.

DST keeps both curves. Switching the mode back restores the inputs, results and revisions of the other mode. Switching the mode clears the location's
verification. In DST Based SRP mode, the active SRP is ready only when the results are current (see [Calculation currency](#calculation-currency)).

### SRP charts

Every system response chart works the same way:

- The legend inside the plot names each curve: **DST Estimate**, and **Revised Estimate** once a node is revised. Pages with more than one pathway
  plot one curve per pathway, such as **Toe Pathway** and **Daylight Pathway**.
- Resting the pointer on a curve shows its values at that point.
- The mouse wheel, or a pinch on a touch screen, zooms the chart; dragging pans it. **Reset zoom** restores the full view.
- **Copy SRP curve data for spreadsheets** copies the curve values to the clipboard, and **Download SRP curves as a CSV file** downloads them. Both
  appear only when the results are current.

### Nodal tables

A system response is built from a sequence of nodes, each the probability of one event in the failure mode. The SRP table summarizes the total at
eight headwaters, which DST chooses to preserve the shape of the full curve. The table has the columns **Headwater Elevation (ft)** (or the page's
horizontal axis), **DST Estimate** and **Revised Estimate**. A page without nodes shows **System Response Probability** in place of the two estimate
columns. The table is read-only; the Revised Estimate column fills from the nodal revisions.

Below the table, **Nodal System Response** opens to show one card per node. Each card names its node and what it represents, shows its probability
range across the eight headwaters (or its single probability, for a node that does not vary with headwater), and carries a **DST** tag, or a
**Revised** tag once the node is revised. A revised card also reads **Needs justification** or **Justification provided**.

nodal revisions together with its results and verification. DST reports a change on another page in a notice; one example reads "Dam Information,
Operational Data or Failure Mode Screening inputs changed since these results were calculated. The results, nodal adjustments, and SRP
verification were cleared; the analysis will recalculate automatically." The first sentence differs between failure modes. The justifications of revised nodes are kept.

:::

## Event Trees

PFM-11, PFM-12, PFM-13, PFM-17, PFM-18, PFM-20, PFM-22 and PFM-23 define their system response with an event tree, as does PFM-21 when the dam has
a concrete type but no Gravity or Roller-Compacted Concrete type (see [Chapter 28, PFM-21: Concrete Dam Instability](./28-pfm-21.mdx)): the team assigns a probability to
each node of the tree at each of a set of reservoir stages, and DST multiplies them along each pathway to breach. These pages share one layout, whose
sections are numbered: **1 Stages to evaluate**, **2 Event tree evaluation**, and then **System Response**. Each failure mode's chapter lists its
own stages, nodes, questions and branches. The SRP mode control reads **Event tree** and **User defined**.

Every entry on an event-tree page saves automatically and clears the location's verification. A change to a source of a default stage, such as the
normal pool on the Stage Duration page, also clears it.

### Mirrored nodes

In trees whose pathways repeat a node, the repeated node can mirror its source node, so the team enters the values once. Mirroring is off by
default. The node panel of such a node has a check box, for example **Mirror Node 2a**:

- **Turning it on.** The node follows its source's values and rationale. Mirrored values show a link icon ("Mirrored from Node 2a"), and the
  rationale shows "Shared with Node 2a until you edit it here."
- **Overriding one stage.** Entering a value at a stage overrides it for that stage only, and the node becomes **Partly mirrors**. A re-link icon
  beside the overridden value discards it and follows the source again ("Discard this value and follow Node 2a again"). **Re-link all** discards every
  override of the node.
- **Editing the rationale** on the mirroring node replaces the shared rationale with its own.
