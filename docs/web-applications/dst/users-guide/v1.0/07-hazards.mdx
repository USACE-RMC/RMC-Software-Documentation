# Hazards

The Hazards module holds the loading the screening is evaluated against. Its three pages are Flood Hazard, the annual exceedance probability of
each reservoir stage; Stage Duration, the share of time the reservoir sits at or above each stage; and Seismic Hazard, the annual exceedance
probability of each level of ground motion. The failure mode pages, Consequences and Risk Analysis read their loading from these pages: the flood-loaded
failure modes from Flood Hazard, and the seismic failure modes from Seismic Hazard and Stage Duration, which also supplies the normal pool
elevation.

Each page has its own verification badge, and changing an input clears its verification (see
[Human Verification](./04-working-in-dst.mdx#human-verification)). When a change makes the results of a later page out of date, DST clears those
results and says so (see [Automatic Calculation](./04-working-in-dst.mdx#automatic-calculation)). Each page also has a summary tray at the bottom
for its justification and supporting documents (see [Summary Tray](./04-working-in-dst.mdx#summary-tray) and
[Supporting Documents](./06-documents.mdx#supporting-documents)).

### Flood hazard summary

The summary tray, **Flood hazard summary**, holds one required section, **Basis of the flood hazard curve**: "The source study or analysis, how the
upper tail was extended, and any judgment applied." The tray status reads "No justification yet" until the user enters it, and "Justification on
file" afterwards. The tray ends with the page's supporting documents (see
[Supporting Documents](./06-documents.mdx#supporting-documents)).

## Stage Duration

The Stage Duration page (**Hazards > Stage Duration**) holds the stage–duration relationship of the reservoir: the percent of time each stage is
equaled or exceeded. DST reads the normal pool elevation from it as the stage exceeded 50% of the time. The seismic failure modes use the relationship
as the reservoir level during an earthquake, and the event-tree failure modes use the normal pool. When the curve cannot give the 50% stage, those
pages use the Dam Data normal pool instead and show the warning "The normal pool can't be taken from the stage-duration curve ([reason]), so the Dam
Data normal pool ([elevation]) is used instead."

### Source

**DST Based** or **User Defined** in the toolbar chooses where the relationship comes from. Each mode keeps its own data, so switching between them
loses nothing; the active mode is the one the rest of the screening uses.

**DST Based** is available when DST holds a reservoir data source, CWMS or RISE, for the dam's NID ID on the Dam Data page. A new screening of
such a dam opens in DST Based mode; any other opens in User Defined mode. When no source is held, **DST Based** is unavailable, and resting the
pointer on it shows "This option is only available for Corps of Engineers and Bureau of Reclamation facilities. Please enter data using the User
Defined Stage Duration method." (<FigReference figKey="dst-users-guide-fig-stage-duration-source-unavailable" />).

### DST Based

In DST Based mode, DST fetches the dam's reservoir stage record from its data source and derives the stage–duration curve from it. The page shows
one of these states:

- **No reservoir data fetched yet.** "Start the initial reservoir-data fetch for this dam, or switch to User Defined to load stage data." with a
  **Fetch reservoir data** button.
- **No DST Based data available.** "This dam has no reservoir data source assigned. Switch to User Defined to load stage data.", shown when the
  page is in DST Based mode but DST holds no source for the dam.
- **Fetching.** "Fetching reservoir data…" with "Pulling stage time series from CWMS (3 of 12 year-chunks complete)." and a progress bar (RISE
  counts pages). The fetch runs in the background; the page updates as it progresses. The page cannot be verified, and its justifications cannot be
  edited, until the fetch finishes.
- **CWMS fetch failed** (or **RISE fetch failed**). "The last fetch did not complete. Re-fetch to try again or switch to User Defined to load data." with a **Re-fetch** button.
- **No reservoir data available.** "No stage time-series data is available for this dam from its reservoir data source. You can reach out to the
  dam owner to obtain stage data, then enter it using the User Defined Stage Duration method.", where **User Defined Stage Duration** switches the
  page to User Defined mode.
- **Reservoir data source under administrator review.** "The assigned reservoir data source is currently unavailable. Administrators can review the global assignment; no action
  is required from you."
- **Fetched.** The status line, the two charts and the trimmed periods, as in <FigReference figKey="dst-users-guide-fig-stage-duration-dst-based" />.

The status line reads **Last fetched:** and the date. The information icon beside it, titled **CWMS data source** (or **RISE data source**), lists
the source's **Office**, **Location**, **Series**, **Sampling interval**, **Normalized to**, **Period of record** and **Datum**, with a map of the dam
and the source location. **Re-fetch** ("Pull a fresh stage time series from CWMS in the background. The current series is replaced and the curve is
recomputed once the fetch finishes. Trim ranges are preserved.") opens the **Re-fetch from CWMS?** dialog; **Continue and re-fetch** starts the
fetch.

When the fetched record covers less than 15 years after trimming, the page shows the warning "The retained period of record is [n] years — shorter
than the 15-year minimum recommended for screening-level analysis. Contact the [district] to inquire whether additional reservoir time series data
is available for the stage duration relationship."

### Vertical datum

DST compares the vertical datum of the fetched record with the screening's datum. When they match, the status line reads that the datum matches,
for example "Datum matches: NAVD88". When the record needs attention, an amber card appears above the charts:

- **Specify the source datum**, when the source published no datum: the user chooses **NAVD88**, **NGVD29** or **Other** (with a name such as "USGS
  1912") and selects **Apply**.
- **Convert to the screening datum**, when the datums differ: the user chooses **ADD** or **SUBTRACT** and enters the offset, a positive number in
  the screening's units, then selects **Apply**.
- **Re-resolve the datum**, when the screening's datum or units changed after the record was reconciled.

Until the datum is resolved, the curve is not used for the normal pool. A converted record shows the conversion on the status line, for example
"NGVD29 → NAVD88 (−0.8 ft)", with **Edit** to change it.

### Charts and trimmed periods

The **Stage time series** chart plots the record's stage against **Date**, and the **Stage–duration curve** chart plots stage against **Exceedance
%**. Each chart has a download button: "Download full time series as a CSV file" and "Download stage-duration curve as a CSV file". The curve chart
draws the Dam Data normal pool as a labeled horizontal line.

When the Flood Hazard curve reaches above the highest observed stage, DST extends the stage–duration curve to the Flood Hazard curve's highest stage
with a dashed line. The line under the curve chart says which applies, for example "Extrapolated above 1,250.00 ft-NAVD88 to 1,262.40 ft-NAVD88 using
the Flood Hazard curve (dashed).", "Not extrapolated: the observed curve already reaches the top of the Flood Hazard curve." or "Not extrapolated: no
Flood Hazard curve has been entered." The information icon on the curve chart heading explains the extension.

A trimmed period is a date range left out of the record, such as a construction period or a gage outage. DST derives the curve from the record
without the trimmed periods. There are two ways to add one:

### User Defined

- **Normal pool elevation** ("Single elevation"): one elevation stands for the whole relationship.
- **Stage time series** ("Paste a stage time series; the DST derives the curve."): the user pastes a stage record, and DST derives the curve from it.
- **Stage–duration relationship** ("Enter the stage / exceedance-% rows directly."): the user enters the curve in a table.

### Stage duration summary

The summary tray, **Stage duration summary**, shows the justification for the active method. Before any reservoir data has been fetched in DST
Based mode, it shows only the section **Stage duration justification**: "No justification is needed until reservoir data has been fetched."

- **Basis of the DST based stage duration** (optional) in DST Based mode.
- **User time series**, **User duration curve** or **Single normal pool elevation** (required) for the User Defined method in use.
- **Trimmed periods**: one justification for each trimmed period that removes records. Each is required. When no period is trimmed, the section
  reads "No periods are trimmed, so no justification is needed."; when the trimmed periods remove no records, it reads "The trimmed periods remove
  no records, so no justification is needed."

Its status reads, for example, "1 trimmed period needs justification" in amber, "No justification yet", "Justification on file" or "No justification
needed". The Submission Readiness page lists a missing required justification, for example "Stage Duration: write a justification for the
user time series (on the Stage Duration page)."

### Source

**DST Based** fetches the curves from the USGS dynamic seismic hazard web service for the dam's coordinates on the Dam Data page. It is available
when the coordinates lie in a region the USGS models cover; otherwise it is unavailable, with the tooltip "Coordinates are outside supported USGS
model regions. Use User Defined mode." A screening opens in DST Based mode where it is available. **User Defined** takes curves the user enters.

### DST Based

Before the first fetch the page reads "No seismic hazard data fetched yet" with **Fetch USGS data** ("Pull Dynamic Seismic Hazard Curves from USGS
in the background."). While the fetch runs, the page reads "Fetching Seismic Hazard Data…" with a progress bar and the site class being queried; the
page cannot be verified until a fetch succeeds. A failed fetch shows **USGS fetch failed**: "The last fetch did not complete. Re-fetch to try again or switch to
User Defined to load data.", with a **Re-fetch** button ("Retry the USGS fetch in the background.") that opens the same **Re-fetch from USGS?**
confirmation described below. When USGS has no data for the coordinates, the page reads "No Dynamic Seismic Hazard data is available for the specified
coordinates."

Once the curves are in place, the status line reads **Last fetched:** and the date, and its information icon, **USGS Data Source**, lists the **NSHM Model**,
the **Coordinates** and the **Service**, with a **Dam location** map. **Re-fetch** opens the **Re-fetch from USGS?** dialog: re-fetching replaces the current curves with a fresh pull
for the dam's current coordinates. When the dam's coordinates change after a fetch, the saved curves no longer match and the page must be fetched
again before it can be verified.

Under **Chart Filters**, the filters **Site Classes**, **Source Components** and **Intensity Measure Types (IMTs)** each choose one or more values. They control only what the
page displays: "These filters only control data visualization for this page. They do not select hazard curves for any seismic potential failure
modes." The table **Summary Table for Common Return Periods** lists, for each plotted curve, the ground motion at return periods of 145, 225, 475, 975, 2,475 and 10,000 years. The
chart plots **Annual Exceedance Probability** against **Ground Motion (g)**.

plots every curve with the selected one emphasized (<FigReference figKey="dst-users-guide-fig-seismic-hazard-user-defined" />). A chip without a
justification is marked. Under the curve table, the **Summary Table for Common Return Periods** lists the ground motion of each curve
at the same return periods as in DST Based mode.

### Seismic hazard summary

The summary tray, **Seismic hazard summary**, holds, in DST Based mode, the optional section **Basis of the DST based seismic hazard**: "Anything a
reviewer should know about the USGS hazard curves, such as the site class chosen and why." In User Defined mode each curve carries its own
justification instead. The tray ends with the page's supporting documents (see
[Supporting Documents](./06-documents.mdx#supporting-documents)).
