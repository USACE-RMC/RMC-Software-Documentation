# Event Trees

An event tree evaluates a failure mode as a sequence of nodes: the team chooses the reservoir stages, assigns each node a probability at each stage
with a rationale, and DST reports the resulting system response. PFM-11, PFM-12, PFM-13, PFM-17, PFM-18, PFM-20, PFM-22 and PFM-23 use an event tree,
as does PFM-21 when the dam has a concrete type but no Gravity or Roller-Compacted Concrete type (see [PFM-21: Concrete Dam
Instability](./367-pfm-21.mdx)). DST multiplies the node probabilities along each pathway to breach. [Common problems](#common-problems) at the end of
this page explains why the curve does not appear or is not passed to the Risk Analysis module.

An event-tree page has the sections **1 Stages to evaluate**, **2 Event tree evaluation** and **System Response**. Each failure mode's page in this
guide lists its own stages, nodes, questions and branches. The SRP mode control reads **Event tree** and **User defined** (see
[Active SRP](./343-system-response.mdx#active-srp)).

Every entry on an event-tree page saves automatically and clears the location's verification. A change to a source of a default stage, such as the
normal pool on the Stage Duration page, also clears it.

## Stages

The **Stages to evaluate** section sets the reservoir stages at which the tree is evaluated, lowest first. At and below the zero point, the
system response is fixed at 1.00E-16 and nodes take no probability.

An added stage's elevation and description stay editable in place. The trash icon deletes the stage with its entered values. A stage added from a
node's panel applies to that node only (see [Nodes](#nodes)).

The **Zero point** column chooses one stage. When the lowest stage is chosen, the zero point follows whichever stage is lowest, so adding a stage
below it moves the zero point down to the new stage. Choosing any other stage fixes the zero point there. Deleting the added stage that holds the
zero point returns the zero point to the lowest stage.

## Nodes

Each node's probability at each stage, and the rationale for its estimates, are entered in the node panel. The panel is headed with the node's number,
title and question. It has one row per stage of the node: the default stages, the stages added for every node and the stages added for this node
only. A node that does not depend on the stage has a single row, **All stages**, marked **Pool independent**.

The slider and the **Probability** box set the same value. The slider moves between its seven stops only; the box takes any value from 0 to 1, and
a typed value between two stops places the slider's handle between them. An empty box leaves the slider without a handle. A node's probabilities
should stay the same or increase from one stage to the next.

**Add stage to this node** adds a stage that only this node uses; the user enters it in the same way as an added stage (see [Stages](#stages)), and
it appears in the Stages table as **Added, Node N only**. Its trash icon deletes it with its value. Pool-independent nodes have no such button.

**Previous node** and **Next node** step through the nodes, starting with those shared by every pathway and then following each pathway.

:::tip

Tab moves between the nodes of the diagram, and Enter or Space opens one, so a tree can be worked through from the keyboard. **Next node** moves
to the next node without returning to the diagram.

:::

## Mirrored nodes

In trees whose pathways repeat a node, the repeated node can mirror its source node, so the team enters the values once. Mirroring is off by
default. The node panel of such a node has a check box, for example **Mirror Node 2a**:

- **Turning it on.** The node follows its source's values and rationale. Mirrored values show a link icon ("Mirrored from Node 2a"), and the
  rationale shows "Shared with Node 2a until you edit it here."
- **Overriding one stage.** Entering a value at a stage overrides it for that stage only, and the node becomes **Partly mirrors**. The re-link icon
  beside the overridden value discards it and follows the source again. **Re-link all** discards every override of the node.
- **Editing the rationale** on the mirroring node replaces the shared rationale with its own.

## Event tree system response

The **System Response** section of an event-tree page shows a table and a chart once every node has a probability at every stage above the zero
point and the stages and probabilities have no errors.

<FigReference figKey="dst-users-guide-fig-failure-mode-evaluation-event-tree-results" /> shows the results of a tree with two branches.

<Figure
  figKey="dst-users-guide-fig-failure-mode-evaluation-event-tree-results"
  src="figures/web-applications/dst/users-guide/v1.0/figures/failure-mode-evaluation-event-tree-results.png"
  alt="The System Response section of a PFM-18 location. A table has the columns Stage (ft-NAVD88), Branch a, Branch b and Total SRP. The row 777.00, at the zero point, is grayed with 1.00E-16 in every column; 788.67 shows 3.00E-08, 9.90E-08 and a total of 1.29E-07; 812.00 shows 1.62E-04, 3.08E-04 and a total of 4.70E-04. A chart plots Branch a, Branch b and Total SRP on a logarithmic System Response Probability axis against Pool Elevation (ft-NAVD88) from 777 to 812, with a legend and a download button."
  caption="The system response of an event tree with two branches."
  width="100%"
/>

- **Table.** One row per stage, with one column per branch (**Branch a**, **Branch b**) when the tree has more than one pathway, and **Total
  SRP**. The information icon on a branch header names the pathway's nodes; the icon on **Total SRP** explains how the branches combine. Resting
  the pointer on a branch value shows its share of the total, such as "62.5% of the total". Stages at or below the zero point are grayed.
- **Chart.** The curves plotted against **Pool Elevation (ft)** on a logarithmic probability axis, with the same zoom, reset and download controls
  as the other SRP charts (see [SRP charts](./343-system-response.mdx#srp-charts)).

The total becomes the location's active SRP in **Event tree** mode. Event-tree pages have no nodal revisions; the team enters the node
probabilities directly.

### How the total is calculated

At each stage above the zero point, each branch is the product, along its pathway, of P for each step that takes a node's Yes outcome and 1 − P for
each step that takes its No outcome, where P is the node's probability at the stage. The **Total SRP** is the sum of the branches. A branch or total
below 1E-16 is raised to 1E-16.

For example, take a tree with two pathways through Nodes 1, 2 and 3, one taking Node 3's Yes outcome and the other its No outcome. With Node 1 at
0.1, Node 2 at 0.5 and Node 3 at 0.2 at a stage, Branch a is 0.1 × 0.5 × 0.2 = 0.01, Branch b is 0.1 × 0.5 × 0.8 = 0.04, and the total is 0.05.

At a stage added for another node only, DST interpolates a node's probability between its own stages, linearly in elevation and in the logarithm
of the probability, starting from 1E-16 at the zero point, and holds it above the node's highest stage.
