# Event Trees

PFM-11, PFM-12, PFM-13, PFM-17, PFM-18, PFM-20, PFM-22 and PFM-23 define their system response with an event tree, as does PFM-21 when the dam has
a concrete type but no Gravity or Roller-Compacted Concrete type (see [PFM-21: Concrete Dam Instability](./367-pfm-21.mdx)): the team assigns a probability to
each node of the tree at each of a set of reservoir stages, and DST multiplies them along each pathway to breach. These pages share one layout, whose
sections are numbered: **1 Stages to evaluate**, **2 Event tree evaluation**, and then **System Response**. Each failure mode's page in this guide lists its
own stages, nodes, questions and branches. The SRP mode control reads **Event tree** and **User defined**.

Every entry on an event-tree page saves automatically and clears the location's verification. A change to a source of a default stage, such as the
normal pool on the Stage Duration page, also clears it.

## Stages

The **Stages to evaluate** section lists the reservoir stages at which the tree is evaluated, lowest first. Its description reads "Stages are listed
lowest first. At and below the zero point, the system response is fixed at 1.00E-16 and nodes take no probability."

The diagram reads left

- **Green with a white check**: complete; it has a probability at every stage above the zero point and an estimate rationale.

selected with the keyboard: Tab moves between them, and Enter or Space opens one. With no node selected, the panel reads "No node selected" and
"Select a node in the event tree to view and assign its probabilities."

## Nodes

The node panel is headed with the node's number and title, followed by the question the node asks. It has one row per stage of the node: the default
stages, the stages added for every node and the stages added for this node only. A node that does not depend on the stage has a single row, **All
stages**, marked **Pool independent**. <TableReference tableKey="dst-users-guide-table-failure-mode-evaluation-node-inputs" /> describes its inputs.

**Add stage to this node** adds a stage that only this node uses; the user enters it in the same way as an added stage (see [Stages](#stages)) and appears
in the Stages table as **Added, Node N only**. Its trash icon deletes it with its value. Pool-independent nodes have no such button.

**Previous node** and **Next node** step through the nodes, starting with those shared by every pathway and then following each pathway, and wrap
around at the ends. A node's probabilities should stay the same or increase from one stage to the next (see
[Event tree messages](#event-tree-messages)).

## Mirrored nodes

In trees whose pathways repeat a node, the repeated node can mirror its source node, so the team enters the values once. Mirroring is off by
default. The node panel of such a node has a check box, for example **Mirror Node 2a**:

- **Turning it on.** The node follows its source's values and rationale. Mirrored values show a link icon ("Mirrored from Node 2a"), and the
  rationale shows "Shared with Node 2a until you edit it here."
- **Overriding one stage.** Entering a value at a stage overrides it for that stage only, and the node becomes **Partly mirrors**. A re-link icon
  beside the overridden value discards it and follows the source again ("Discard this value and follow Node 2a again"). **Re-link all** discards every
  override of the node.
- **Editing the rationale** on the mirroring node replaces the shared rationale with its own.

## Event tree system response

The **System Response** section of an event-tree page shows a table and a chart once every node has a probability at every stage above the zero
point and the stages and probabilities have no errors. Until then it reads "No system response curve yet" and "The curve appears once every node has
a probability at every stage above the zero point and the stages and probabilities have no errors."

<FigReference figKey="dst-users-guide-fig-failure-mode-evaluation-event-tree-results" /> shows the results of a tree with two branches.

- **Table.** One row per stage, with the columns **Stage (ft)**, one column per branch (**Branch a**, **Branch b**) when the tree has more than one
  pathway, and **Total SRP**. The information icon on a branch header names the pathway's nodes and shows the tree with the pathway highlighted; the
  icon on **Total SRP** explains how the branches combine. Resting the pointer on a branch value shows its share of the total, such as "62.5% of the
  total". Stages at or below the zero point are grayed.
- **Chart.** The curves plotted against **Pool Elevation (ft)** on a logarithmic probability axis, with the same zoom, reset and download controls as
  the other SRP charts (see [SRP charts](./343-system-response.mdx#srp-charts)).

The total becomes the location's active SRP in **Event tree** mode (see [Active SRP](./343-system-response.mdx#active-srp)). Event-tree pages have no nodal revisions; the team enters the node
probabilities directly.
