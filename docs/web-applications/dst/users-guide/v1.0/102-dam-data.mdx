# Dam Data

The Dam Data page holds the dam's identity, types, dimensions, key elevations and reservoir data. The user reaches it from
**Screening Information > Dam Data**. For a dam taken from the NID, DST fills the page from the dam's NID record when the screening is created, and
each value shows whether it still matches the NID. For a dam entered manually, the team enters every value.

Inputs on this page save automatically (see [Saving](./040-working-in-dst.mdx#saving)): text and number fields when the user leaves them, and
selections as soon as they are made. Changing any value clears the page's verification (see
[Human Verification](./040-working-in-dst.mdx#human-verification)). The Facilitator, Team Members and administrators can edit the page while the screening's inputs are
open for editing; everyone else sees it read-only.

## NID values and overrides

For an NID dam, the label of every field filled from the NID carries a small badge:

- **NID** (blue) — the value matches the NID record.
- **Edited** (amber) — the team changed the value. Resting the pointer on the badge shows the NID value and the date DST fetched it.

Selecting an **Edited** badge opens a small panel that shows the **Current** value and the **NID** value
(<FigReference figKey="dst-users-guide-fig-dam-data-reset-to-nid" />). **Reset to NID** returns the field to the NID value, and **Cancel** closes the
panel. Some fields reset together: Latitude and Longitude, the dam types, and the spillway types. When more than one of them changed, the panel lists
each one under "Reset these fields to NID values?".

  alt="The Structural Height field on the Dam Data page of Blue Marsh Dam – User's Guide Example, with its amber Edited badge selected. A small panel below the badge is titled 'Reset Structural Height (ft) to NID value?' and lists Current 98 and NID 100, the NID value in blue, above Cancel and Reset to NID buttons."
  caption="Resetting an edited value to the NID value."
  width="50%"
/>

Each changed value needs a justification when the NID supplied a value for the field. The justification chip beside the field's label is a pencil
outlined in amber while the justification is missing, and a check mark once it is written. Selecting the chip opens a box headed by the field name,
with the note "The NID value is" followed by the NID value
(<FigReference figKey="dst-users-guide-fig-dam-data-override-justification" />). The user enters the reason, up to 4,000 characters, and the
justification saves when the box closes. The same justifications appear in the [Dam data summary](#dam-data-summary) tray. A field the NID left blank
needs no justification when the team fills it in.

A justification is kept when its field is reset to the NID value or re-fetched, and it is shown and required again if the field is changed again. A
missing justification leaves the Dam Data page Incomplete on the Submission Readiness page (see
[Submission Readiness](./040-working-in-dst.mdx#submission-readiness)). Writing or changing a justification clears the page's verification.

:::note

The page does not show the dam's hazard potential classification. For an NID dam, DST copies it from the NID when the screening is created, and a
re-fetch can update it (it appears in the re-fetch comparison as **Hazard Class**). It cannot be entered or changed in DST, so a screening of a dam
entered manually has none.

:::

## Re-fetching from the NID

The NID updates its records over time. When the NID has changed a field this screening uses since the screening's copy was fetched, a note titled
"The NID has newer data for this dam" appears below the NID data bar. It gives the date of the NID update, the number of fields changed and the version
the screening uses.

**Re-fetch from NID** compares the screening's values with the current NID record and opens a comparison below the NID data bar
(<FigReference figKey="dst-users-guide-fig-dam-data-refetch-preview" />). The button is available to the Facilitator, Team Members and administrators while the
screening's inputs are open for editing, and only for a dam with a Federal ID. Without one, the button is unavailable and resting the pointer on it
shows "No NID link — add a Federal ID to enable". The button is also unavailable while a comparison is open, until the user applies or cancels it.

  figKey="dst-users-guide-fig-dam-data-refetch-preview"
  src="figures/web-applications/dst/users-guide/v1.0/figures/dam-data-refetch-preview.png"
  alt="The re-fetch comparison panel below the NID data bar on the Dam Data page of Blue Marsh Dam – User's Guide Example; the Re-fetch from NID button is unavailable while the panel is open. The summary line reads '0 NID updates will apply · 2 edits kept'. A Your edits (2) table, with Keep all mine and Use NID for all at its right, has columns Field, Your value and NID: Structural Height 98 against 100, and Normal Storage 21800 against 22897, each row ending in a Keep mine / Use NID control with Keep mine selected. Apply and Cancel buttons sit at the bottom of the panel."
  caption="Comparing the screening with the current NID record."
  width={MEDIA_WIDTH}
/>

- **NID updates** lists the fields whose NID value changed and that the team has not edited, with the **Current** and **NID** values. These values
  are replaced when the comparison is applied.
- **Your edits** lists the fields the team changed, with **Your value** and the **NID** value. Each row has a **Keep mine** / **Use NID** choice;
  **Keep mine** is selected to start. **Keep all mine** and **Use NID for all** set every row at once when there are two or more. "NID changed since
  your edit" marks a field whose NID value changed after the team edited it, and shows the earlier NID value before the new one.
- The summary line above the tables counts the updates that will apply, the edits kept and the edits that will be replaced. When nothing differs, it
  reads "No values differ from the NID. Applying updates this screening's NID record date."

**Apply** saves the result and updates the NID record date and the fetch date. **Cancel** closes the comparison without changing anything. Applying
a comparison that changes any value clears the page's verification and has the same effects on other pages as editing those values.

The comparison covers every NID field the screening keeps, not only those on this page. Besides the fields described below and **Hazard Class**,
it can list **City**, **Hydraulic Height**, **NID Height**, **Federally Regulated**, **EAP Meets Guidelines**, **USACE Dam**, **USACE District** and
**DSAC Class**. The page does not show these values and the team cannot edit them, so a change to one always appears under **NID updates** and is
applied with the rest. **USACE Dam** matters elsewhere: for an Official screening of a USACE dam, the search for a new Facilitator on the Screening
Management page lists only members of the USACE Facilitators group, so a re-fetch that changes it changes who can be chosen (see
[Team management](./104-screening-management.mdx#team-management)).

<VideoReference videoKey="dst-users-guide-video-dam-data-refetch" /> shows a re-fetch comparison: setting a row to **Use NID** or **Keep mine**
updates the count of NID updates and kept edits at the top, and **Cancel** discards the comparison.

## Dam & spillway types

clears it. Both are required (<TableReference tableKey="dst-users-guide-table-screening-information-dam-data-types" />). The dam types decide which
cross sections, materials and potential failure modes apply to the screening on the Response pages.

## Key elevations & storage

The **Key Elevations & Storage** section holds the dam's design elevations, from the dam crest down to the streambed, each with the reservoir storage
at that level (<TableReference tableKey="dst-users-guide-table-screening-information-dam-data-elevations" />). Elevations are on the screening's
vertical datum, for example ft-NAVD88, and storage is in acre-ft or m³. Other pages start from these elevations, such as the stage-duration curve,
the failure mode pages and the reference lines on the Operational Data charts; changing one of them on those pages needs a justification there. The table has
the columns **Level**, **Elevation** and **Storage**, with a row for each level; each level's name has a **Required** or **Optional** tag and a
question-mark button with its definition.

## Dam data summary

The **Dam data summary** tray at the bottom of the page collects the page's justifications and supporting documents
(<FigReference figKey="dst-users-guide-fig-dam-data-summary-tray" />). [Summary Tray](./040-working-in-dst.mdx#summary-tray) describes how the tray
opens and closes. For an NID dam, its status reads "No NID overrides", or counts the overrides and any that still
need a justification, for example "2 NID overrides · 1 needs justification", in amber while a justification is missing.

- **NID overrides** (NID dams only, **Required** while any override exists) lists each changed field, with the NID value and the current value, for
  example "NID 100 → 98", and its justification. Each justification can be written or edited here as well as from the field's chip; it saves when the

## Dam data messages

The page messages button reports each missing required value as a required input (see [Page Messages](./040-working-in-dst.mdx#page-messages)).
When the key elevations sit oddly against each other, DST instead reports a warning as a notice in the lower right corner each time the page saves;
the warnings never block submission. "Provide the Spillway Crest Elevation." appears only when Controlled or Uncontrolled is selected. When the
only dam type is a general NID classification, the Dam Type message names it, "Concrete" or "Other".

The Dam Data page is Ready on the Submission Readiness page when every required value is present, every required justification is written and the page
is verified.

Dam Data feeds other modules, so a change here can change other pages:

- Changing the **Latitude** or **Longitude**, on this page or on the Overview map, retrieves the seismic hazard data for the new location (see
  [Seismic Hazard](./203-seismic-hazard.mdx)).
- Changing the **Normal Pool** elevation changes the default normal pool on the Stage Duration page and can clear that page's verification (see
  [Stage Duration](./202-stage-duration.mdx)).
- Changing the dam types or the **Dam Crest** elevation can change which potential failure modes apply and update Failure Mode Screening (see
  [Failure Mode Selection](./330-failure-mode-selection.mdx)).
- Changes to Dam Data can clear the verification of failure mode locations whose evaluation uses the changed values (see
  [Verifying a location](./342-failure-mode-pages.mdx#verifying-a-location)).
