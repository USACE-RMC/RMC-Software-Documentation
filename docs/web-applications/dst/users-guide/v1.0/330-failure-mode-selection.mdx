# Failure Mode Selection

Use this page to decide which potential failure modes (PFMs) the screening evaluates, and to record a rationale for each one excluded. The page is
at **Response > Failure Mode Selection**. It lists every PFM that DST covers, grouped by the part of the dam and the loading, with DST's
recommendation and the team's decision for each. Only the PFMs set to evaluate appear on the Failure Mode Evaluation page and in the risk analysis.

## Groups and Failure Modes

The groups are **Earth Embankment — Flood**, **Earth Embankment — Seismic**, **Spillway — Flood**, **Concrete Dam — Flood**, **Concrete Dam —
Seismic** and **User Defined**. Each row names its failure mode by number and name, for example **01 - Embankment Overtopping Erosion**. Some rows
take no decision:

- A group heading reads "Not applicable" with a reason, such as "No concrete dam type in Dam Data", when the dam has nothing it applies to. A single
  failure mode can also be marked **N/A**; resting the pointer on it gives the reason, such as "No conduit recorded in Dam Information".
- A failure mode that DST cannot yet evaluate reads **Coming soon** ("DST does not have an evaluation workflow for this failure mode yet.").

## Recommendations

The **DST** column shows DST's recommendation as a pill. <TableReference tableKey="dst-users-guide-table-failure-mode-screening-and-selection-recommendations" />
lists the recommendations. Resting the pointer on a pill shows "Screening recommendation: Evaluate" or "Exclude", "Your decision overrides it:
Exclude" (or Evaluate) when the team's decision differs, and a note on what led to the recommendation, including how any Unknown answers were
treated.

The first time a firm Evaluate or Exclude recommendation appears for a failure mode, DST sets the team's decision to match it. After that, DST never
changes a decision; it flags the change instead (see [Recommendation changes](#recommendation-changes)).

## Decisions

The **Evaluate** toggle records the team's decision: on evaluates the failure mode and carries it to the Failure Mode Evaluation page, and off
excludes it. A failure mode with a Pending or None recommendation starts **Undecided** ("Not decided yet — toggle on to evaluate"); selecting the
toggle chooses Evaluate, and selecting it again chooses Exclude. Decisions save as soon as they are made.

Excluding a failure mode deletes nothing. Its locations, inputs, results and justifications are kept while it is excluded, but it leaves the
Failure Mode Evaluation page and the risk analysis, and its pages cannot be opened. Switching it back to Evaluate brings its locations back with
their inputs. A failure mode switched to Evaluate for the first time starts with one location.

The **Status** column shows what each failure mode still needs:

- **Undecided**: no decision yet.
- **Add rationale**: the failure mode is excluded and needs a rationale. Selecting it opens the rationale dialog.
- **DST rationale**: excluded with DST's rationale only. Selecting it opens the dialog to read it or add the team's own.
- **Rationale**: excluded with the team's own rationale.
- **Review change**: DST changed its recommendation after the team decided (see [Recommendation changes](#recommendation-changes)).

### Adding an exclusion rationale

Every excluded failure mode needs a rationale, and a DST rationale alone meets the requirement. The **Exclusion rationale** dialog shows **DST
rationale (read-only)** when DST supplied one, or **No screening recommendation** with DST's note when it made none, and a **User rationale** box of
up to 4,000 characters for the team's reason. **Save** stores it and **Cancel** closes the dialog.

The page messages list each failure mode still undecided ("1 failure mode needs an Evaluate or Exclude decision.") and each exclusion without a
rationale, for example "PFM 08 - CLE due to Desiccation Cracking at the Crest is excluded from evaluation without a rationale." These are required
inputs (see [Page Messages](./040-working-in-dst.mdx#page-messages)).

## Recommendation Changes

When later inputs change DST's recommendation for a failure mode the team has already decided, its row is highlighted amber and its status reads
**Review change**. <FigReference figKey="dst-users-guide-fig-failure-mode-selection-review-change" /> shows the review.

Selecting **Review change** opens a popover that states the change, for example "DST recommendation changed: Exclude → Evaluate", and the team's
decision. **Keep** keeps the decision and **Switch to** changes it; either one confirms the review. Until the team confirms it:

- the page messages list "PFM 08 - CLE due to Desiccation Cracking at the Crest: DST now recommends Evaluate (was Exclude). Use Review change on its
  row to confirm your decision." (the clause in parentheses appears when there was an earlier recommendation);
- the failure mode's rows on the Failure Mode Evaluation page read **Needs confirmation**, and its failure mode pages cannot be opened (see
  [Opening a location](./341-locations.mdx#opening-a-location));
- the failure mode is left out of the risk analysis.

A save on any page whose inputs the recommendations read, such as Failure Mode Screening, Dam Information or Flood Hazard, can change a
recommendation. A notice then names each failure mode whose recommendation now differs from the team's decision, for example "The DST
recommendation changed for PFM-08 and PFM-10. Confirm your decision for each on the Failure Mode Selection page." The risk analysis lists the same
failure modes until they are confirmed, such as "The DST recommendation for PFM-08 changed. Confirm your decision on the Failure Mode Selection
page; until then PFM-08 is left out of the risk analysis." (see [Risk Analysis Setup](./501-risk-analysis-setup.mdx)).

A change is flagged only when the new recommendation is a firm Evaluate or Exclude that differs from the team's decision and has not been confirmed
before. A recommendation that returns to match the decision needs no review, and user-defined failure modes are never flagged.

## User-Defined Failure Modes

Use **Add failure mode** in the **User Defined** group to add a failure mode that DST does not cover. The new row's box reads "Name this failure
mode, then click away to save"; the name, up to 200 characters, saves when the user leaves the box, and an empty name adds nothing. DST numbers
user-defined failure modes from PFM 28 and adds each one set to Evaluate, with no DST recommendation; switching it to Exclude needs a rationale.

The pencil icon (**Rename**) edits the name in place; Enter or leaving the box saves it. The trash icon (**Remove**) opens the dialog "Remove PFM
28?" (with the failure mode's number), which warns that the failure mode "and any evaluation data entered for it will be permanently deleted. This
cannot be undone." **Remove** deletes it and **Cancel** keeps it.

Removing a user-defined failure mode moves every user-defined failure mode numbered above it down by one; for example, removing PFM 28 makes PFM
29 the new PFM 28. Names, decisions, rationales and evaluation data move with them.

:::caution

Removing a user-defined failure mode deletes it and its evaluation data permanently.

:::

## Verifying the Selection

The screening team verifies the page as a whole with the verification badge in the sub-navigation bar (see
[Human Verification](./040-working-in-dst.mdx#human-verification)). DST clears its verification when the team changes a decision or rationale,
or adds, renames or removes a user-defined failure mode. It also clears it when DST adopts a first-time Evaluate recommendation, when a
recommendation changes for a failure mode in evaluation, and when a change on the Dam Data or Dam Information page changes which failure modes
apply.

## Common Problems

### The Evaluate toggle and Add failure mode are unavailable

The user cannot edit the screening, or its inputs are locked (see [Input Lock](./040-working-in-dst.mdx#input-lock)). Resting the pointer on the
toggle shows the decision only, such as "Exclude".

### A failure mode has no toggle

It reads **Coming soon**, **N/A** or sits in a group marked "Not applicable". These rows take no decision. For **N/A** and "Not applicable", the
reason names the data to check, such as "No conduit recorded in Dam Information".

### A failure mode's pages cannot be opened

The failure mode is excluded, or its recommendation changed and is waiting for review (**Needs confirmation** on the Failure Mode Evaluation page).
The user switches its toggle to Evaluate, or selects **Review change** on its row and chooses **Keep** or **Switch to**.

### The page messages list an exclusion without a rationale

"PFM 08 - CLE due to Desiccation Cracking at the Crest is excluded from evaluation without a rationale." The user selects **Add rationale** on the
row and enters a **User rationale** (see [Adding an exclusion rationale](#adding-an-exclusion-rationale)).
