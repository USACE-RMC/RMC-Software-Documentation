# Setup

Before the risk can be computed, each failure mode requires a consequence function. The Setup page (**Risk Analysis > Setup**) assigns these
functions and identifies the failure modes that still need input. Selecting **Risk Analysis** in the module navigation opens it.

## Assigning Consequence Functions

The setup table has one row per failure mode, with a row beneath it for each of its locations, and a **Total** row.
<TableReference tableKey="dst-users-guide-table-risk-setup-columns" /> lists its columns. The one input on the page is the **Consequence Function**
of each failure mode; it saves when chosen (see [Saving](./040-working-in-dst.mdx#saving)). The locations share their failure mode's function.

The **Response** column shows the state of each row's system response curve:

- **Defined** means the row has an active system response curve. Selecting it opens a **System Response Preview** of the curve, from the "DST
  curve" or a "User-defined curve", with **Linear** and **Log** buttons for the probability axis. Selecting **Defined** again, selecting outside the
  preview, or pressing <kbd>Esc</kbd> closes it.
- **Composite** appears on a failure mode with locations. Its response combines its locations, which share the failure mode's consequence function.
- **Evaluate →** appears when no system response curve is defined yet, and opens the Failure Mode Evaluation page (see
  [Failure Mode Evaluation](./340-failure-mode-evaluation.mdx)).

The **Consequence Function** drop-down lists the failure functions from the Results Data page. A function with nothing to send yet is listed but
cannot be chosen, and a row still assigned such a function shows its name grayed out. A location row shows its failure mode's function, with the
tooltip "Shared by all locations; select the consequence function on the failure-mode row".

The failure mode rows show marginal risk. The **Total** row is the system-combined (adjusted) result, computed once every row is complete. An
incomplete row has an amber edge, and the page messages give the reason.

## Non-Failure Consequences

The **Non-failure consequences** row names the non-failure function chosen on the Results Data page. It applies to every failure mode: it gives the
background risk, and DST compares it with each failure function to find the excess life loss and damages. It is read-only here; **Change on Results
Data** (or **Select one on Results Data** when none is chosen) opens that page. The info button explains how the non-failure consequences are used.

With no non-failure function, the row reads "None selected: taken as zero", and with one that has no results yet, "[name]: nothing to send yet,
taken as zero". In both cases the background consequences are taken as zero.

## Compute Status and Export

The status beside the table reads "Computing…", "Computed [time]", "[K] of [N] failure modes need input" or "Not computed". The risk recomputes
whenever an input upstream changes.

**Export to TotalRisk** downloads an RMC-TotalRisk project (.tra) with the system diagram and one diagram for each failure mode location, for life
loss and economic cost. It does not need a computed result.

## Risk Preview

The **Mean Risk Plot for Excess Societal Risk** plots each failure mode, once its inputs are complete, and the **Total (adjusted)**, as annual
probability of failure against expected life loss given failure, with the tolerable risk guideline line for EALL = 1E-03. Failure modes with an
APF below 1E-07 are not plotted and are listed in a footnote. The full results are on the Results page (see
[Results](./502-risk-analysis-results.mdx)).

## Common Problems

[Page Messages](./040-working-in-dst.mdx#page-messages)). The common messages and their resolutions are:
