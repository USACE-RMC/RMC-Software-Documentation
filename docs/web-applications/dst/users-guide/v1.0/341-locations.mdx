# Locations

A failure mode can be evaluated at more than one place on the dam. Each such place, such as one abutment, one conduit or one cross section, is a
location, and the location actions on the Failure Mode Evaluation page manage them. Each location has its own failure mode page, inputs, system response and
verification. A failure mode starts with one location when it is selected for evaluation.

The row menu (three dots) at the end of each row holds the location actions. <FigReference figKey="dst-users-guide-fig-failure-mode-evaluation-row-menu" />
shows the menu of a failure mode with one location, and <TableReference tableKey="dst-users-guide-table-failure-mode-evaluation-row-menu" /> lists the menu items.

Some failure modes allow only one location, and some create their locations from the screening's data, such as one location per abutment. The
page for each failure mode in this guide says which applies.

## Adding a Location

To add a location, the user chooses **Add location** from the row menu of a failure mode with one location, or selects **Add location** (+) on the
parent row of a failure mode with several locations. DST adds an empty location named **Location N**, where N is the new number of locations. Its
status reads Incomplete until its system response is defined.

## Copying a Location

**Copy location** adds a location that starts with the same inputs, overrides, justifications and results as the row it was copied from. DST names
it after the source with **(copy)** added, for example **Left Abutment (copy)**. The copy is not verified. For a failure mode with one location, the
copy is made from that location.

A **Not started** location has nothing to copy, so copying it adds an empty location under the copy name instead.

:::tip

Copying a location that is already set up is the most efficient way to evaluate a similar section: the copy keeps the inputs, and only the values that
differ need to change. A copy of a copy keeps the single suffix, so the user renames each copy to tell them apart.

:::

## Renaming a Location

The user renames a location in the **Location** box of its failure mode page (see
[The page toolbar](./342-failure-mode-pages.mdx#the-page-toolbar)). The new name shows in the table, in the breadcrumb and on the location's
Submission Readiness tile.

**Rename location** in a location's row menu opens the **Rename location** dialog with a **Location name** box. **SAVE** shows the new name in the
table, and **CANCEL** closes the dialog without a change.

:::note

A name entered in the **Rename location** dialog shows in the table only until the page reloads. To keep a new name, the user enters it in the
**Location** box of the failure mode page.

:::

## Deleting a Location

**Delete location** in a location's row menu removes that location with its inputs, results, justifications and verification. A failure mode always
keeps at least one location, so the item appears only on failure modes with two or more locations. Links from the location to files on the
Documents page are removed; the files themselves remain (see [Documents](./150-documents.mdx)).

:::caution

**Delete location** acts at once, with no confirmation, and cannot be undone.

:::

## Opening a Location

Selecting a failure mode or location name, or **Open failure mode** in its row menu, opens the location's failure mode page. The sub-navigation then
shows a breadcrumb such as **Failure Mode Evaluation › PFM-01 · Left Abutment**; selecting **Failure Mode Evaluation** returns to the table (see
[Modules and pages](./040-working-in-dst.mdx#modules-and-pages)). DST saves any entry still in progress before leaving a failure mode page.

## Common Problems

- **Add location, Copy location, Rename location or Delete location is missing.** The failure mode allows only one location, or DST creates its
  locations from the screening's data; such locations cannot be added, renamed or deleted from the table. The location actions are also hidden for
  users who cannot edit the screening's inputs, while inputs are locked (see [Input Lock](./040-working-in-dst.mdx#input-lock)), and while the
  failure mode needs confirmation on the Failure Mode Selection page.
- **Delete location is missing on a failure mode with one location.** A failure mode always keeps at least one location. To stop evaluating it, the
  team excludes the failure mode on the Failure Mode Selection page.
- **A new name goes back to the old one after the page reloads.** The name was entered in the **Rename location** dialog, which does not keep it.
  The user enters the name in the **Location** box of the failure mode page instead.
- **A blank location name is not saved.** DST keeps the last saved name; on most failure mode pages the page reports "Name cannot be empty." The
  user enters a name.
- **A failure mode page shows "PFM-01 isn't being evaluated"** (with the failure mode's number), reading "This failure mode isn't selected for
  evaluation on Failure Mode Selection. Select it for evaluation there to open its locations." The team selects the failure mode for evaluation on
  the Failure Mode Selection page (see [Failure Mode Selection](./330-failure-mode-selection.mdx)).
