# System Response

The system response probability (SRP) is the probability of the failure mode's system response at each headwater elevation (or at each overtopping
depth, on PFM-01). DST calculates it automatically once the characterization is complete. The **System Response** section of a failure mode page
presents and exports the location's SRP and holds revisions to individual nodes; alternatively, the curve can be entered directly. [Common
problems](#common-problems) at the end of this page covers results that do not show, revisions that disappear and warnings on a user-defined SRP.

While the system response recalculates, the chart shows a placeholder curve. Some pages show an input above the table that sets the range of the
curve, such as the maximum depth evaluated; each failure mode's page in this guide describes it.

## Active SRP

The SRP mode in the toolbar chooses the location's active SRP: the curve DST passes to the Risk Analysis module and shows in the System Response
Preview.

- **DST Based SRP** (**Event tree** on the event-tree pages): the curve DST calculates from the page's inputs, including any nodal revisions.
- **User Defined SRP** (**User defined**): a curve the user enters in a table (see [User-defined SRP](#user-defined-srp)). The page replaces its
  characterization and system response sections with the table and its chart.

DST keeps both curves, so switching the mode back restores the inputs, results and revisions of the other mode. Switching the mode clears the
location's verification. In DST Based SRP mode, the active SRP is ready only when the results are current (see
[Calculation currency](#calculation-currency)).

## SRP charts

Every system response chart works the same way:

- The legend names each curve: **DST Estimate**, and **Revised Estimate** once a node is revised. Pages with more than one pathway plot one curve
  per pathway, such as **Toe Pathway** and **Daylight Pathway**.
- Resting the pointer on a curve shows its values at that point.
- The mouse wheel, or a pinch on a touch screen, zooms the chart; dragging pans it. **Reset zoom** restores the full view.
- **Copy SRP curve data for spreadsheets** copies the curve values to the clipboard, and **Download SRP curves as a CSV file** downloads them. Both
  appear only when the results are current.

### The SRP CSV file

The downloaded file opens with comment lines, each starting with "#", that record the failure mode, the dam, screening and location, the date and
time generated, the SRP mode ("SRP mode: DST (calculated)" or "SRP mode: User Defined"), whether nodal revisions were applied, and when DST last
calculated the location. Two tables follow: the calculated curves, such as one column per node beside the total, and the active SRP curve, headed,
for example, "Active SRP curve (DST) — the curve risk calculations consume", which is the curve passed to the Risk Analysis module. Times are in
UTC.

## Nodal tables

A system response is built from a sequence of nodes, each the probability of one event in the failure mode. The SRP table summarizes the total at
up to eight headwaters that DST chooses to preserve the shape of the full curve. Once a node is revised, the probability column becomes **DST
Estimate** and **Revised Estimate**, and the revised rows are highlighted. The table is read-only; the Revised Estimate column fills from the nodal
revisions.

Below the table, **Nodal System Response** opens to show one card per node. Each card names its node, shows its probability range across the
headwaters (or its single probability, for a node that does not vary with headwater), and carries a **DST** tag, or a **Revised** tag once the node
is revised. A revised card also reads **Needs justification** or **Justification provided**.

The node's chart and the Revised Estimate column of the SRP table update as the user types, and the revisions save shortly after each change.
Revisions do not recalculate the system response; DST combines the revised nodes into the Revised Estimate curve, which becomes the active SRP. In
the node's chart, a small triangle at the top edge marks each headwater at which a curve reaches 1.

### How the Revised Estimate is combined

At each headwater, the Revised Estimate is the DST Estimate multiplied by the ratio of revised to DST estimate of every revised node, and never less
than 1E-16. Between a node's headwaters the ratio is interpolated linearly, and beyond the first and last it is held at the end values. A blank
revised cell, or a DST estimate of zero, leaves the node as DST estimated it there.

For example, where the DST Estimate is 1.0E-03, revising one node from 0.50 to 0.25 gives a Revised Estimate of 5.0E-04. Revising a second node
from 0.80 to 0.40 at the same headwater halves it again, to 2.5E-04.

### Reverting revisions

Three buttons undo revisions, each after a confirmation dialog whose **Continue and revert** button proceeds:

- **Revert to DST Estimates** in the node dialog clears that node's revised estimates and keeps its headwaters.
- **Revert to DST Headwaters** in the node dialog replaces that node's custom headwaters with DST's.
- **Revert to DST Estimates** beside the Nodal System Response heading clears every revised estimate and custom headwater of the location.

<VideoReference videoKey="dst-users-guide-video-system-response-revert" /> shows the location-wide **Revert to DST Estimates** beside the Nodal System
Response heading: the dialog "Revert all nodes to DST estimates?" opens, **Continue and revert** confirms it, the Revised curves leave the chart and
the table returns to the DST values.

and a chart of the curve they define. <TableReference tableKey="dst-users-guide-table-failure-mode-evaluation-user-srp-inputs" /> describes the

The table starts with two rows. Until it holds values, the chart reads "Enter values in the table to plot the system response curve." The table
saves shortly after each change, and the curve becomes the active SRP. The table works like the other tables in DST (see
[Tables](./040-working-in-dst.mdx#tables)).

:::tip

A curve kept in a spreadsheet pastes directly into the table: the user copies the two columns, selects the first cell and pastes, and the table
adds rows as needed. Pressing Tab in the last cell also adds a row.

:::

## Common problems

These problems apply to the System Response section of every failure mode page. For a system response that does not calculate at all, see
[The system response does not calculate](./342-failure-mode-pages.mdx#the-system-response-does-not-calculate).

### A notice shows in place of the results

The stored results cannot be confirmed as current. The notice says whether DST is recalculating on its own or the results must be recalculated;
[Calculation currency](#calculation-currency) lists each notice and what to do. Until the results are current, the location is not Defined and
cannot be verified.

### The nodal revisions disappeared

An input on the page, or on a page the location reads, changed, and DST recalculated the system response. Recalculation clears the nodal revisions
with the results and the verification; the justifications are kept. The team enters the revisions again against the new DST estimates.

### A nodal revision is not saved

DST does not save a revision that breaks these rules, and reports why:

- "Node [node] needs at least 2 headwater values to interpolate an SRP curve."
- "Node [node] headwaters must be strictly increasing; [x] at position [n] is not greater than the previous value [y]." The user corrects the
  headwater, or selects **Revert to DST Headwaters**.
- "Node [node] revised probabilities must be between 0 and 1."

### The copy and download buttons are missing

They appear only when the results are current. The user waits for the calculation to finish, or resolves the notice shown in place of the results.

### Warnings on a user-defined SRP

DST reports these warnings in the page messages; the curve is still saved:

- "SRP curve is empty." The table holds no points.
- "First headwater ([x] ft) is above the minimum hazard headwater ([y] ft). Consider adding a point at or below the minimum headwater with
  probability 0."
- "Probability decreases from [p] at HW=[x] to [q] at HW=[y]. SRP curves should be monotonically non-decreasing."
- "Probability [p] at HW=[x] is negative. Probabilities must be between 0 and 1." or "... exceeds 1. Probabilities must be between 0 and 1."
- "Headwater values are not strictly increasing. HW=[x] at index [n] is not greater than HW=[y]."
