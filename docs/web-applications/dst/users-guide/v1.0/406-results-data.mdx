# Results Data

Each inundation analysis becomes a consequence function once its loading levels are simulated. The Results Data page (**Consequences > Results
Data**) presents each function as graphs and as the tables the risk analysis receives. The page also designates the non-failure function and holds
functions entered by hand.

## Consequence functions

Each function has a card. **Download all (.csv)** saves every function's table as the risk analysis receives it.

- **Add function** adds a function entered as tables, with a **Name** (up to 100 characters, unique) and a **Role** (Failure or Non-failure). Such
  a function can be renamed or deleted from its card.
- When two functions share a name, the later ones are numbered, for example "Overtopping (2)".

### Choosing the non-failure function

One function can be the non-failure function, the baseline every failure function is compared with; every other function is a failure function.
An analysis starts as a failure function if any of its loading levels has a breach turned on, and as a non-failure function otherwise. Until a
function is chosen, DST proposes the first function whose role is non-failure.

To choose the non-failure function, the user selects its **Non-fail** button ("Make [name] the non-failure function. Only one function can be
non-failure."). Every other function then becomes a failure function, whatever its breach settings.

In an analysis where some levels have the breach on and others off, the levels with it off are left out, with the note "Some loading levels have a
breach turned on and others have it off; those with it off are left out."

## Graphs and tables

**Graphs** shows the function's **Life loss** as a box per loading level with its mean, and its **Economic damages** as bars by damage category,
both against stage. Notes below say which levels are left out and why, such as a level that is out of date or not run, and how the function is held
beyond its lowest and highest stages.

**Tables** lists the rows the risk analysis receives. <TableReference tableKey="dst-users-guide-table-consequences-function-rows" /> lists the
columns. DST's rows, from the loading levels, are read-only. User-defined rows can be added, pasted and edited like any DST table (see
[Tables](./040-working-in-dst.mdx#tables)); they sort by stage and save as they are entered, and a user row at a level's stage replaces the
level's row.

### Carrying a function across the hazard curve

The risk analysis needs each table to cover the whole stage range of the flood hazard curve. DST adds rows at the ends of each table to carry it
across the curve, shown as **DST, held below**, **DST, held above** or **DST, zero below** in the **Source** column:

- A failure function holds its lowest point's value down to the curve's lowest stage, and its highest point's value up to the curve's highest
  stage, for example "Held at 0.57 below 812 ft, down to 790.6 ft."
- The non-failure function is zero below its lowest point ("Zero below [stage].") and holds its highest point's value above.
- A table with one point is carried as that value at every stage: "One current level, so it would go as a constant: [value] lives at every stage."
- A table with no point, beside one that has some, is treated as zero: "The [table] table has no point, so it goes as zero at every stage."

## Loading level summary and plots

For a function from an analysis, the **Loading level** selector chooses one level. **Summary** shows its mean life loss and 5–95% range, mean damages,
population at risk, life loss ÷ population at risk, first water and the share warned and leaving, the inputs it **Ran with**, and its **Damages by
category**. **Plots** shows life loss across the iterations, life loss by the time of day, when people left before the water arrived, and the warning
and evacuation steps from population at risk to lives lost.
