# Getting Started

This page covers obtaining an account and signing in, finding and opening screenings on the Dashboard, creating and copying screenings, managing a
screening team and updating the Profile page. [Working in DST](./040-working-in-dst.mdx) covers the work within an open screening: navigation, saving,
verification and the other behaviors shared by every screening page.

## Signing In

DST's home page is public. **Request Access** asks for an account, and **Log In** opens the Log In dialog
(<FigReference figKey="dst-users-guide-fig-getting-started-log-in" />). Following a link to a DST page while signed out opens the Log In dialog, and
after signing in the user goes on to the page the link pointed to.

A checklist under the password fields marks each requirement as it is met and flags **passwords match** while the two entries differ. **Show**

DST then confirms "Account request submitted" and emails the user when the request is received and again when it is approved or denied. Once
approved, the user signs in with the email address and password from the request.

### Logging in

**Log In** offers two ways to sign in:

- **Sign in with Login.gov** sends the user to Login.gov and back to DST signed in. The first time, DST links the Login.gov identity to the DST
  account with the same email address.
- **Email and password.** The user selects **or sign in with email**, enters **Email** and **Password**, and selects **LOG IN**. The email form opens
  on its own the next time for a user who last signed in this way.

After signing in, the user arrives at the Dashboard, or at the page a link pointed to. Messages about a refused sign-in are listed in
[Common problems](#common-problems).

### Forgotten passwords and locked accounts

DST administrators handle password resets and account unlocks:

- **Forgot password?** beside the Password field opens the **Forgot Password** dialog. The user enters the account's email address and selects
  **Submit Request**. Once an administrator approves the request, DST emails the user a temporary password. At the next sign-in the **Set New
  Password** dialog requires a new password: the user enters **New Password** and **Confirm Password** and selects **Update Password**, or selects
  **Log Out**.
- **Locked account.** After five failed sign-in attempts the Log In dialog shows the **Account Locked** view, with **I FORGOT MY PASSWORD** and
  **REQUEST UNLOCK**. The account stays locked until an administrator acts on the request, and DST emails the user when the unlock request is received
  and again when the account is unlocked.

A user who signs in only with Login.gov has no DST password; **Forgot password?** sets one if the user also wants to sign in by email.

### Staying signed in

A session ends after 15 minutes without activity. Two minutes before it ends, a **Session Expiring** notice counts down; **Stay Logged In** keeps the
session open. When a session ends, the **Session Expired** dialog asks the user to sign in again over the page the user was on, so work continues where
it stopped. **Logout** in the avatar menu ends the session (see [The site header](./040-working-in-dst.mdx#the-site-header)).

Selecting a column heading sorts the table by that column, and selecting it again reverses the order. The table opens sorted by **Modified**, newest
first, and **Status** sorts in workflow order. On phones and tablets the table appears as cards, which cannot be sorted.

A screening's **Type** is set when it is created:

- **Official**: a screening of record that can be submitted for review and approval.
- **Testing**: a practice screening. It cannot be submitted for review, never appears in the Search Catalog, and shows **N/A** for its status.

An Official screening shows one of these statuses:

- **In Progress**: the screening team is entering and evaluating the screening. A screening also returns to In Progress if a review lead rejects it.
- **Submitted**: the Facilitator has submitted the screening. The first review level starts immediately, so this status is usually brief.
- **Under Review**: a review level is in progress. Inputs are locked except during a review level's resolution period.
- **Complete**: every review level is approved.
- **No Facilitator**: the screening lost its Facilitator, for example because the Facilitator's account was deactivated. Inputs stay locked until a
  new Facilitator is assigned.

[The Review Lifecycle](./700-review.mdx#the-review-lifecycle) describes the review behind these statuses.

#### Finding a screening

The filter bar narrows the list:

- **Status**: All, In Progress, Submitted, Under Review, Complete or No Facilitator.
- **Type**: All, Official or Testing.
- **Per page**: 15, 25 or 50 screenings per page.
- **Search**: matches any part of the screening name, dam name or description; a whole number also matches that screening ID.
- **All screenings** (administrators only): lists every screening in DST.

Each active filter appears as a chip; × on a chip removes that filter, and **Clear all** removes them all. When more screenings match than fit on one
page, the page controls below the table move between pages.

:::tip
Pressing **/** anywhere on the Dashboard moves the cursor to the search box, and pressing **n** opens the New Screening dialog.
:::

### My Reviews

The **My Reviews** tab lists the review levels on which the user is a reviewer
(<FigReference figKey="dst-users-guide-fig-dashboard-my-reviews" />). Assignments are grouped into three tables:

(<FigReference figKey="dst-users-guide-fig-dashboard-new-screening-dam-search" />).

The selected Facilitator becomes the screening's Facilitator and is notified, and the user who created the screening joins its team as a Team Member.
For every other screening, including any Testing screening, the user who creates it becomes its Facilitator.

### After the screening is created

DST opens the new screening's Screening Information page. Every new screening starts with two review levels, Level 1 and Level 2. When the dam has a
latitude and longitude, DST retrieves its seismic hazard data during creation, and reports a warning only if that retrieval has a problem. DST also
collects reservoir data for the stage-duration curve in the background, which may take a few minutes to appear on the Stage Duration page.

## Managing Screenings

From the Dashboard, the Facilitator manages the screening team and renames the screening until it is submitted, and anyone on the screening can copy
it.

### Managing the screening team

**Manage Team** in a screening's row actions opens the Manage Team dialog (<FigReference figKey="dst-users-guide-fig-dashboard-manage-team" />). It is
available to the screening's Facilitator and to administrators.

  caption="The Manage Team dialog."

- **Facilitator**: shows the screening's Facilitator. An administrator can select **Replace** to assign a different Facilitator while the screening
  is In Progress or Testing; the previous Facilitator loses access to the screening.
- **Team Members**: the role drop-down switches a person between Team Member and Viewer, and the remove icon removes the person from the screening.
- **Add Member**: the user searches active users by name or email, chooses the role in the drop-down, and selects **+ Add as Team Member** or
  **+ Add as Viewer** on the person.

Every change takes effect immediately, with no confirmation step. Reviewers are assigned to each review level on the Screening Management page instead
(see [Review configuration](./104-screening-management.mdx#review-configuration)).

While a screening is under review, Team Members and Viewers can still be added and removed, but the Facilitator stays fixed. Once a screening is
Complete, or while it needs a Facilitator, only Viewer access can be changed. The dialog states which of these applies.

### Copying a screening

**Copy** creates a new screening from an existing one. Anyone on the screening can copy it.
The **Copy Screening** dialog names the copy "(Copy)" followed by the original name and asks for its **Type**, which defaults to the original's. The
user becomes the Facilitator of the copy, except for an Official copy of a USACE dam, which needs a USACE Facilitator (see [USACE dams](#usace-dams)).

A copy holds only the screening's starting information:

- the description, vertical datum and units;
- every Dam Data value, with the NID link, the record of which values differ from the NID and their justifications;
- the documents, each keeping its links to pages except links to failure mode locations.

Everything else starts empty: Operational Data curves, Hazards, the Response pages, Consequences, Risk Analysis and Major Findings. Its Dam Data is
unverified. Its team holds only its Facilitator (and, for an Official copy of a USACE dam with a different USACE Facilitator, the user who made the
copy as a Team Member). The copy has none of the original's review levels, reviewers or review history; it starts with its own Level 1 and Level 2.
DST confirms "Screening copied" and opens the copy on its Screening Information page.

### Renaming a screening

**Rename** opens a dialog with the screening's current name. The user edits the name (up to 200 characters) and selects **Rename**; DST confirms the
new name. A screening can be renamed only while it is In Progress or Testing. If another user changed the screening at the same moment, DST refreshes
the page without applying the rename, and the user renames it again.

## The Profile Page

The user's name and password are changed on the Profile page. **View Profile** in the avatar menu of the site header opens it
(<FigReference figKey="dst-users-guide-fig-getting-started-profile" />).

<Figure
  figKey="dst-users-guide-fig-getting-started-profile"
  src="figures/web-applications/dst/users-guide/v1.0/figures/getting-started-profile.png"
  alt="The Profile page for Jordan Hale, role Member. Personal Information holds editable First Name and Last Name fields and read-only Email, Organization Type (Federal) and Organization (U.S. Army Corps of Engineers). Change Password holds Current Password, New Password and Confirm New Password fields, an unavailable Change Password button and the password requirements."
  caption="The Profile page."
  width="70%"
/>

- **Personal Information**: **First Name** and **Last Name** save when the user leaves the field, and **Saving…** appears while a save is in
  progress. **Email**, **Organization Type** and **Organization** cannot be changed here.
- **Change Password**: the user enters **Current Password**, then **New Password** and **Confirm New Password**, which must meet the same requirements
  as a new account's password and differ from the current one, and selects **Change Password**. DST confirms "Password changed".
